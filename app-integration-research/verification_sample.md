# Official Documentation Review — Results

**Outcome:** 8 of 8 reviewed apps had official documentation supporting a documented API/authentication path and the broad feasibility classification used in this review.

| App | Official evidence reviewed | Key integration consideration |
|---|---|---|
| HubSpot | [Remote MCP documentation](https://developers.hubspot.com/docs/apps/developer-platform/build-apps/integrate-with-the-remote-hubspot-mcp-server) | OAuth/PKCE, scopes and account-tier constraints |
| Shopify | [Authentication documentation](https://shopify.dev/docs/api/usage/authentication) | Token flows, scopes and API-specific policies |
| Slack | [OAuth installation](https://docs.slack.dev/authentication/installing-with-oauth/) | OAuth app installation and workspace scopes |
| Linear | [OAuth 2.0](https://linear.app/developers/oauth-2-0-authentication) | OAuth2 and GraphQL authorization |
| Salesforce | [REST API guide](https://resources.docs.salesforce.com/latest/latest/en-us/sfdc/pdf/api_rest.pdf) | OAuth and edition/org policy constraints |
| Notion | [API documentation](https://developers.notion.com/) | Integration token/OAuth authorization |
| GitHub | [REST API documentation](https://docs.github.com/en/rest) | PAT, OAuth and GitHub App auth options |
| Stripe | [API reference](https://stripe.com/docs/api) | API keys, Connect OAuth and production onboarding |

The result is 8/8 agreement on the broad API/auth feasibility label for the reviewed sample. It should not be interpreted as a score for the full 100-app inventory.
